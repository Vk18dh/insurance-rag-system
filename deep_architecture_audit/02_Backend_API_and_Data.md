# PART 5 — COMPLETE BACKEND ARCHITECTURE
**1. Entry Point:** `backend/app/main.py` creates the FastAPI app.
**2. Middleware:** `HTTPLoggingMiddleware` (logs requests/responses) and `CORSMiddleware` (allows frontend to talk to backend) are attached.
**3. Authentication:** `backend/app/dependencies/auth.py` contains `get_current_user` which verifies the JWT token sent in the `Authorization: Bearer` header.
**4. Routers:** Requests hit `routers/query.py`, `routers/auth.py`, `routers/conversations.py`, `routers/expert.py`, `routers/admin.py`.
**5. Services:** Routers call Services (e.g. `ConversationService`, `ReviewService`) in `backend/app/services/` to handle business logic.
**6. Orchestrator:** `routers/query.py` hands the AI logic over to `phase2/orchestrator/orchestrator.py`.
**7. Agents & LLM:** Agents execute sequentially, fetching data via ChromaDB/BM25, and processing text via `LLMProviderManager`.
**8. Database:** Services write state (messages, review tasks) to PostgreSQL via Repositories (e.g. `UserRepository`).
**9. Response:** A Pydantic model (`QueryResponse`) is returned to the frontend as JSON.

# PART 21 — DATABASE ARCHITECTURE

The system explicitly uses **three distinct data stores**, each tailored for a completely different mathematical operation.

### 1. PostgreSQL (Application Relational Database)
**Why used:** Perfect for rigid, highly structured relational data with ACID compliance. 
**Actual Models (`backend/app/models/`):**
- **`User`**: Stores `username`, `hashed_password`, `role`.
- **`Conversation`**: Stores `title`, links to `User`.
- **`Message`**: Stores `role` (user/assistant), `content`, links to `Conversation`.
- **`ReviewTask`**: Central HITL model. Stores `status` (PENDING, RESOLVED), `reason`, `payload` (JSON snapshot of what the AI was thinking), `expert_decision`.
- **`AuditLog`**: Stores `action` (e.g., QUERY_SUBMITTED), `actor_id`, `safe_metadata`.

### 2. ChromaDB (Vector Database)
**Why used:** SQL databases cannot search by "meaning". ChromaDB stores the vectors generated by the embedding model and performs Cosine Similarity searches instantly.
**What it stores:** Only the PDF document chunks (text) and their corresponding vectors (lists of floats), along with tiny metadata dicts (filename, page).

### 3. Rank-BM25 (Sparse Keyword Index)
**Why used:** ChromaDB struggles with exact keyword matching (e.g. searching for a specific alphanumeric policy ID). BM25 acts like a classic search engine.
**What it stores:** An in-memory frequency map of exactly how many times a specific word appears in a specific document.

# PART 27 — ERROR HANDLING
**401 Unauthorized:** JWT token missing or expired. Handler: `get_current_user`. User Response: Redirected to login page.
**403 Forbidden:** User has `role="user"` but tried to hit `/api/v1/expert/tasks`. Handler: RBAC dependencies. User Response: Access Denied.
**429 Too Many Requests:** Sent by Groq API. Handler: `LLMProviderManager` catches it, sets a cooldown timer, and instantly fails over to local Ollama.
**LLM Verification Failure:** The VerificationAgent determines the retrieved text does not answer the question. Handler: `query.py` catches the `AgentEscalationException`, creates a `ReviewTask` in Postgres, and returns a 200 OK safe refusal message to the user ("I'm escalating this to an expert").
