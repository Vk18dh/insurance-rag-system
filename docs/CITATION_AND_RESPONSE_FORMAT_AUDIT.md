# Citation and Response Format Audit

## 1. Trace Analysis

**Query Flow:**
1. **USER QUERY** is received by `backend/app/routers/query.py`.
2. Passed to `AgentOrchestrator` which invokes `RetrievalAgent`.
3. `RetrievalAgent` returns `RetrievalResult` with `ranked_evidence` (which contains `DocumentChunk` with raw text, metadata, page numbers, etc.).
4. `VerificationAgent` validates the chunks.
5. `ReasoningAgent` uses the chunks to build a `ReasoningChain`. The LLM maps its deductions to `SupportingEvidence` objects. These objects store `chunk_id`, `source_document`, and `page_number`, but **NOT** the raw text snippet.
6. `ResponseBuilder` (specifically `ResponseComposer`) calls:
   - `CitationService.build_citations(reasoning_result)`: Creates `Citation` objects for each `SupportingEvidence`. Because the `snippet` is missing from `SupportingEvidence`, it explicitly hardcodes `snippet=None`. It creates IDs like `[1]`, `[2]`.
   - `ResponseFormatter.format_answer(reasoning_result)`: Passes the raw deduction to the `qwen2.5:3b` / `OpenRouter` LLM. The prompt **forces** the LLM to use a verbose markdown skeleton (`### 🔎 Analysis`, `### 💡 Policy Findings`, `### 📝 Conclusion`) and does **not** provide the `[1]`, `[2]` citation mappings for the LLM to use.
7. **API Response (`query.py`)** iterates over the `Citation` objects to build `RetrievedSource` objects. Because `snippet` is `None`, it defaults to `content_snippet=""`.
8. **Next.js Frontend** receives the `QueryResponse`.
   - `answer-display.tsx` renders the verbose markdown output (with the ugly headings) using standard `react-markdown`.
   - `citations-panel.tsx` renders the `sources` in an accordion, but the `content_snippet` is empty. The citations in the text (which don't exist because the LLM wasn't told to use them) cannot be clicked.

## 2. Root Cause Analysis

**Why are citations lost/fabricated?**
- The LLM generating the final user-facing text is completely blind to the `[1]`, `[2]` mapping generated by `CitationService`.
- If the LLM generates a citation like "The policy explicitly states", it's hallucinating the reference style because it was told to write a "highly detailed, professional conversational response" without being given actual citation IDs.
- The `content_snippet` is lost because `CitationService` does not have access to the original `VerificationResult.retrieval_result` (which holds the chunk text) to extract the text.

**Why is the format verbose/academic?**
- `ResponseFormatter.format_answer` strictly forces the LLM to use the markdown skeleton: `### 🔎 Analysis`, `### 💡 Policy Findings`, `### 📝 Conclusion`.

**Why does the UI not feel premium?**
- The `answer-display.tsx` just dumps the markdown. There is no inline citation parsing.
- The `citations-panel.tsx` is an accordion that looks generic.
- The text lacks the clean, minimal aesthetic of ChatGPT.

## 3. Required Changes

1. **Backend (`ResponseFormatter.py`):**
   - Rewrite the LLM prompt. Remove the rigid markdown skeleton.
   - Inject the `[1] Source Name (p. X)` mappings into the prompt so the LLM can place `[1]`, `[2]` directly inline in its prose.
2. **Backend (`ResponseComposer.py` & `CitationService.py`):**
   - Update `CitationService.build_citations` to accept `VerificationResult` alongside `ReasoningResult`.
   - Match the `chunk_id` in `SupportingEvidence` against `VerificationResult.retrieval_result.ranked_evidence` to safely extract and truncate the actual `snippet`.
3. **Frontend (`answer-display.tsx` & `citations-panel.tsx`):**
   - Update the UI to render `[1]` inside the markdown as custom clickable pill badges (e.g., `<sup className="citation-pill">[1]</sup>`).
   - Refine the `citations-panel` to be cleaner, dropping the empty quote boxes when snippets are missing, or showing the actual snippet if present.
   - Refine the general aesthetics (typography, spacing, borders) to match a "premium insurance AI assistant".

## 4. State of Metadata Preservation
- Current citation data structure: `RetrievedSource` in API.
- Source metadata originates from ChromaDB via `RetrievalAgent`.
- Page numbers ARE preserved in `SupportingEvidence` (if available).
- Chunk IDs ARE preserved.
- Document names ARE preserved.
- The LLM is currently NOT receiving the `[1]` citation identifiers during the final formatting phase.
- Citations in the API response ARE generated by the backend (`CitationService`), but the inline references in the text are currently missing.
